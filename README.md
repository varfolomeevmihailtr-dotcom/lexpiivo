# [LEX]PIIVO — штаб клана Last Asylum: Plague

Сервер 347 · Главный сайт: https://varfolomeevmihailtr-dotcom.github.io/lexpiivo/LEX-PIIVO-site/#home

## Разделы
- Герои, календарь, гайды, исследование и здания
- Калькуляторы ресурсов и прокачки
- «Мой кабинет» (`#cabinet`) — ник, мощность, роль и облачный прогресс
- «Участники клана» (`#members`) — список зарегистрированных и ручные записи для тех, кто ещё не создал аккаунт
- Регистрация и вход (`LEX-PIIVO-site/login.html`) — ник, почта, пароль

## Права доступа
- **Участник**: видит состав, меняет только свой ник, свою мощность и свой личный прогресс
- **R4**: может добавлять и редактировать ручной состав, менять мощность зарегистрированных игроков
- **R5**: права R4, удаление ручных записей и назначение ролей R4 для обычных участников
- **Администратор**: права R5 и назначение ролей R5. Администратора можно назначить только напрямую в БД владельцем проекта

Все права принудительно проверяются Supabase (RLS/SQL), а не только UI.

## Хранение
Supabase (с приватным `player_profiles`) используется для вошедших игроков. Прогресс также кешируется в браузере отдельно для каждого аккаунта. До регистрации сайт сохраняет прогресс локально. JSON-экспорт/импорт остаётся в настройках как резервная копия.

**Обрати внимание**: записи «игрок без аккаунта» не связываются автоматически с зарегистрированным аккаунтом; нужно проверить дубликаты.

## Разработка и безопасность
- Основной сайт: `LEX-PIIVO-site/` в ветке `main`
- Для публикации GitHub Pages источник — `main / (root)`
- Корневой `index.html` перенаправляет в папку приложения
- Для Supabase в браузере используется только **publishable key**; secret/service_role ключи никогда не должны попадать в GitHub Pages
- Supabase Authentication → Email: включить Email, по решению администратора отключить подтверждение почты
- Не отключать RLS на таблицах `clan_accounts`, `clan_members`, `player_profiles`
- Рекомендуется включить защиту от скомпрометированных паролей, если доступна в тарифе

## Координация клана (октябрь 2026)

- **Запись на ивенты** (`#events`): R4/R5 создают мероприятие, указывают местное время события и при необходимости отдельно время открытия/закрытия записи. Нужно опубликовать событие и включить запись. Автоматически закрывается при начале ивента. Участники выбирают «Участвую», «В резерве» или «Не смогу». Лимит мест при «Участвую» проверяется в PostgreSQL, дополнительная регистрация идёт в резерв.
- **Журнал нарушений** (`#incidents`): общие инциденты для клана. Три независимых статуса: написали (жёлтый), сожгли в игре (красный), извинился (зелёный). Редактируют R4/R5, читают все вошедшие пользователи.
- **Актуальные данные** (`#live`): внешний открытый источник LastAsylum.gg — БМ альянса, место на сервере, топ-10 альянсов и участников, список действующих/истёкших по источнику кодов. Только публичные факты, не официальное API игры.
- **Состав из игры** (`#sync`): автоматически загруженный снимок игрового состава и его сравнение с регистрациями на сайте по Unicode-никам. R4/R5 могут подтвердить ручную привязку зарегистрированного игрока к записи из игры.
- **Запасной импорт**: на `#sync` офицер может загрузить JSON выгрузки со страницы альянса LastAsylum.gg, если автоматический источник временно недоступен.

## Бесплатное обновление данных

Workflow: `.github/workflows/lex-data-sync.yml`, скрипт: `scripts/lastasylum_sync.py`.

- GitHub Actions: ежедневно **06:17 и 18:17 UTC** (в Варшаве +1/+2 часа в зависимости от сезона)
- Публичный JSON: `LEX-PIIVO-site/live.json`
- Не требуется секрет, платный сервер или ключ 37GAMES
- Скрипт проверяет robots.txt, запрашивает только несколько публичных страниц и сохраняет предыдущий успешный снимок при ошибке
- На сайте показывается дата последнего успешного получения данных и предупреждение об устаревании
- История БМ альянса: последние 120 успешных обновлений, чтобы сравнивать рост
- **Важно**: это сканирование независимого фанатского сайта, не прямое подключение к игре; обновление LastAsylum.gg может запаздывать. Не используйте его данные как доказательство участия/выхода игрока без проверки.

## Безопасность
В браузере нет service_role ключей Supabase. Для записи на мероприятия используется `set_event_response` с серверной проверкой роли, срока регистрации и лимита мест. Изменения общей базы защищены RLS и серверными функциями; обычный участник не может назначать себе R4/R5.
